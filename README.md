# contract-ref-cycle-web

契约引用工作台。修复了 `$ref` 解析与错误展示：

## 服务端 (`src/server/refs.ts`)

- 递归状态拆成两部分：
  - **当前递归栈 `stack`**：仅包含本分支正在展开的引用链；目标已在栈中才是真实循环。
  - **已解析缓存 `resolved`**：先前分支完整展开过的共享节点直接复用，同一 `definitions` 节点可被任意多处引用（菱形、扇出），不会被误判为循环。
- 状态在每次解析时新建，不跨请求、跨位置泄漏。
- 真实循环返回结构化问题，包含完整引用链（首节点在末尾重复）、稳定的实例路径与 schema 路径；直接递归与间接递归都给出每一跳。
- 缓存键为规范化的 `docUri#pointer`，不携带"首次访问路径"。含问题的子树不缓存，因此每个引用位置都报告自己的实例路径（缓存结果不会把首次位置带到后续位置）。
- 正常共享节点只展开一次：解析次数按**不同节点数**计，不随引用数量线性增长（测试覆盖 50 处共享引用只展开 1 个节点）。
- 远程文档每份只加载一次；远程失败、指针无效分别报告为 `remote_unavailable` / `invalid_pointer`，不影响文档其余部分解析。
- 未通过禁止递归 schema 或关闭缓存实现。

## 前端 (`src/client/issues.ts`, `src/client/App.tsx`)

- 错误按 **实例路径 + schema 路径** 的稳定组合标识；同一 schema 在多个实例位置复用时各自独立。
- 数据刷新后通过 `reconcileExpanded` 保留仍存在的展开项、移除已失效项，新错误不自动展开——旧路径不会残留并指向另一个节点。
- 单调递增的请求序号保证快速切换示例时只有最新请求能渲染（慢响应的旧示例不会覆盖新示例），切换时立即清空旧预览。

## 场景覆盖

测试（`npm test`，24 项）覆盖：菱形引用、直接与间接循环、同一 schema 在多实例位置复用、远程引用失败、快速切换示例、并发请求隔离。

```
npm install
npm run dev      # 服务端 :4174，前端 :4173
npm test
npm run build
```

三个内置示例：orders（菱形共享）、profiles（直接 + 间接递归，两处实例位置）、inventory（远程引用成功与失败各一）。
